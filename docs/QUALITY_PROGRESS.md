## 検査方法

- `tests/unit/physicsRegression.test.ts`：監査の最小故障再現、相対接触時刻、同時命中、同tickの上下得点、予約／出現中の再開、支柱、反転、数値異常。
- `tests/unit/geometry.test.ts` と `tests/property/collision.property.test.ts`：端点／角の法線、必ず接触する例、必ず外れる例、独立した距離評価。nullを返すだけで通らない検査にする。
- `tests/unit/boardValidator.test.ts`：実形状の間隔、全盤面の180度回転対称、候補別の再開配置、有限値の反例。
- `npm run audit:physics`：基準と同じ3盤面×2難易度×4自動戦法×100seed＝2,400試合。純粋な固定更新を呼び、外部へ得点を送らない。
- `npm run format:check`、`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`、既存の3ブラウザーの導線検査。

2,400試合の自動戦法は無操作、中央固定(180,320)、左固定(140,320)、通常パックの現在位置への追尾。充電が戻ると、入力可能なx=24〜336／y=24〜548の対象へ撃つ。試合時間90秒、seed1〜100、上限20,000更新。人の反応や端末の描画遅延を含まないため、人の勝率・面白さの評価には使わない。

無得点20秒超は「一度でも2,400更新を超える無得点区間があった試合数」。物理変更で得点・勝率が変わることは許容し、正常終了・重なり・実際の再開配置の安全性を合格条件とする。得点停止中の凍結位置を再出現位置と取り違えず、`GOAL_PAUSE`を抜けた瞬間の配置を測る。

## 第2段階（H01〜H03）の実装結果

2026-09-09に、盤面を見失わずに操作できる配置、充電状態の明示、Pointer入力の端末縮尺差を対象に実装した。

- `inputCoordinates.ts` でCanvasのCSSピクセルを360×640の論理盤面へ変換し、矩形が取得できない場合だけPhaser座標へ安全に戻す。
- 現行ブラウザではCanvasのネイティブPointer Eventsを優先し、CSSピクセルを論理座標へ変換する。有効な指の `setPointerCapture()` と `lostpointercapture` を使い、画面外移動・ブラウザ取消・中断・キーボード切替時に後発射しないようにした。Pointer Events非対応ブラウザには従来のPhaser経路を残す。
- 試合画面は、短い勝ち方と発射状態を先頭へ置き、PCでは盤面と案内を2列、幅720px以下では盤面を先に表示する。
- 充電ゲージへ状態別の色、明示的な割合（例：`充電 63%`／`満タン（100%）`）、残り秒数を表示する。Safariのネイティブ`progress`表示も同じ配色へ固定した。
- タッチと細かいポインタを同時に持つ端末は「タッチ／PC操作」として両方の案内を残す。

単体検査は17ファイル153件、format/lint/typecheck/buildは成功した。Playwrightの縮尺入力検査はテストコードを追加したが、この環境にはChromiumの実行バイナリがないためローカル実行は未確認。CIとiPhone 17 Pro Safari実機確認を残す。

## 第2段階の追補（画面固定と4画面導線）

2026-09-10、試合中にページ全体が揺れて操作しにくくなる問題を、画面の大きさが決まらないままPhaserの縮尺処理とCSSが互いに再計算していたことが主因と判断した。次の変更を追加した。

- ホーム、モード選択、ゲーム、結果を1つずつ表示する画面枠として扱い、現在の画面を`data-screen`で明示する。説明と設定はホームから開く補助画面として残す。
- ゲーム中は`100svh`の固定ビューポートへ切り替え、文書のスクロールと引っ張り移動を止める。画面を切り替える時だけ先頭へ戻し、試合中の描画更新ではスクロール位置を変更しない。
- 盤面枠を9:16の固定比率にし、スマホでは盤面を先に置いて案内を省スペース化する。Canvasは枠いっぱいに収め、画面内で縮尺が変わっても360×640の論理座標を維持する。
- Phaserの縮尺モードを`NONE`、親要素の自動拡張を無効にし、DOM側の固定枠と二重にサイズを管理しない。これにより、親要素とCanvasのサイズが往復する再計算を防ぐ。
- モード選択の見出しを「遊ぶモードを選ぶ」へ変更し、試合中にも「押して狙い、指を離して撃つ」を短く残した。

単体検査153件、format/lint/typecheck/buildは成功。固定ビューポート、9:16比率、画面切り替え後のスクロール停止は、CIのChromium／WebKit／Firefoxブラウザ検査で確認済み（run #468）。iPhone 17 Pro Safariでの実機確認は未実施。

今回の変更で物理規則は触っていないが、既存の3盤面×2難易度×4戦法×100seed（2,400試合）を再実行した。24条件すべてで`invalid=0`、`overlapMatches=0`、`unsafeRoundResetMatches=0`だった。勝敗や無得点区間はゲームバランスの診断値として扱い、今回の画面固定の合否には使わない。

## 第3段階（H13）の実装結果

2026-09-11、基本説明から「射撃場」を開けるようにした。射撃場は通常のゲーム画面と同じCanvas、Pointer／キーボード入力、固定更新、弾とパックの衝突、充電待ちを使う。一方で、CPU、試合時計、2点コア、無得点圧力は止め、外しても時間切れにならず何度でも試せるようにした。

- 白いパックが静止した状態から始まり、弾が実際に命中すると「命中しました」と表示する。
- 命中後に上の赤いゴールへ入れると「練習完了」を表示し、条件選択へ戻れる。
- 射撃場からホームへ戻る操作と、説明を飛ばして通常の条件選択へ進む操作を残した。
- 射撃場用の物理状態で、時計が進まず、CPU弾が出ず、外した弾の寿命後も次の発射が可能であることを単体試験で確認した。

単体試験は156件、format/lint/typecheck/buildは成功した。Playwrightはこの環境にブラウザ実行バイナリがないためローカル実行は未確認だが、射撃場の導線検査をCIへ追加した。iPhone 17 Pro Safariでの命中・得点、初見の理解、持ち替えやすさは未確認として残す。
